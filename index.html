01 // The Problem

The Fog of Modern Systems.

Modern operating systems juggle hundreds of processes, multi-core scheduling, and complex memory paging. When your machine slows down, traditional task managers display a blizzard of raw numbers without context.

CASE FILE 01

The Silent Thermal Throttle

"Why is my PC hot and loud when I'm just reading an article?"

Background update services and telemetry workers constantly schedule micro-bursts across high-performance CPU cores. Standard task managers miss them because average CPU usage looks low, but thermals spike.

OSD translates core frequency and sustained sample pressure into thermal-aware alert signals.
CASE FILE 02

The Vanishing Memory Mystery

"Where did 32 GB of RAM go? No single app shows more than 800 MB."

Modern browser architectures split tabs across 40 isolated processes. Looking for "one big memory hog" fails because memory exhaustion is caused by distributed process proliferation.

OSD groups sibling instances into aggregate application footprints and tracks swap memory thrashing.
CASE FILE 03

The Dangerous Guesswork

"Can I terminate this process, or will Windows blue-screen?"

Generic managers give you a raw "End Task" button with zero safety guidance. Users guess blindly, risking crashes or terminating critical background tasks.

OSD enforces kernel exclusion safeguards protecting dwm.exe, lsass.exe, and system-critical drivers.
02 // The Signature Methodology

Observe. Understand. Act. Verify.

How OSD turns raw OS telemetry into calm, decisive computer maintenance.

STAGE 01

Observe

High-cadence hardware telemetry continuously samples CPU core saturation, memory allocations, pagefile swap pressure, disk I/O queues, and socket throughput.

• psutil native C-hooks
• Windows PSAPI calls
• Thread-independent timing
STAGE 02

Understand

Deterministic correlation engine filters out harmless compiler spikes while detecting authentic bottlenecks, runaway threads, and memory growth velocity.

• Weighted health scoring
• Multi-sample windowing
• Runway exhaustion models
STAGE 03

Act

Non-destructive recommendations provide clear next moves. When user approval is given, targeted memory trimming or process containment executes under strict protection rules.

• Kernel blacklist safeguards
• Identity re-validation
• Zero automatic guesswork
STAGE 04

Verify

Every corrective action is followed by differential telemetry auditing: measuring exact freed megabytes, CPU drop, and resulting health score gains recorded to SQLite WAL.

• Before/after differentials
• SQLite persistent audit
• Health score gain verification

05 // Architecture & Trust

Zero Telemetry. 100% Local.

OSD is designed on a simple principle: your operating system telemetry belongs solely to your machine. No accounts, no cloud endpoints, and no remote data exfiltration.

Technical Stack

Host Instrument Architecture

Built with CPython 3.12, Windows native PSAPI hooks, and Qt PySide6 for desktop rendering. The local web companion runs via Python's embedded socket server without external node runtimes.

Hardware Sampler psutil 7.0 + Win32 PSAPI hooks
Diagnostic Cadence 1.5s background thread (thread-isolated)
Local Database SQLite 3 with Write-Ahead Logging (WAL)
Local Storage %LOCALAPPDATA%/OSD/osd.db
Kernel Safety

Protected Process Blacklist

OSD embeds hardcoded kernel guards. It is structurally impossible for automated or user-initiated actions to terminate Windows system-critical binaries.

Protected Kernel System, ntoskrnl.exe, smss.exe, csrss.exe
Protected Services services.exe, lsass.exe, svchost.exe, dwm.exe
Security Services MsMpEng.exe, securityhealthservice.exe
Cloud Transmissions 0 bytes sent. Fully offline.
